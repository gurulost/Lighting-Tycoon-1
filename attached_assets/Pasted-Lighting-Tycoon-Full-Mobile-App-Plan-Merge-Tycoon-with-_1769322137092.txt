Lighting Tycoon — Full Mobile App Plan (Merge Tycoon with a “Lock‑In Villain”)
One‑line pitch
Run a neon-lit lighting workshop where you drag-to-merge parts into install kits, fulfill house orders for cash + reputation, and decide whether to use the Bulb Baron’s shiny locked components (fast gains, long-term dependency) or build open-standard tech and eventually a Freedom Controller to break the lock-in.

1) Design pillars (non‑negotiables)
One crisp verb:
Drag-to-merge on a single board. Everything else supports it.
Micro-sessions by default:
30–90 seconds of “merge → fulfill → upgrade → done,” with instant pause/resume.
Clarity in the first minute:
The first 60 seconds are scripted to guarantee success: merge twice, complete one order, upgrade once, see the villain choice once.
“Juice” is functional feedback:
Every merge produces readable change (tier label + icon + glow), and felt change (haptic tick + snap sound + particle burst).
Meaningful choice with real tradeoffs:
Locked parts feel great early but raise Dependency that later forces locked installs or refunds. Open-standard is slower early but stable late.
Progression is the product:
Players return for: bigger board, better drops, new orders, story beats with the Bulb Baron, and the long-term R&D goal.
Ethical monetization posture:
No forced ads, no pain-to-sell-relief traps. If monetized: opt-in rewarded ads and cosmetics, with transparent value.

2) The core loop and how it feels in 30–90 seconds
Core loop (seconds–minutes)
Generate parts (tap workbench / open crates)
Merge up the chain
Clips → Tracks → Segments → Smart Kits → Premium Systems
Fulfill orders (consume kits)
Earn cash + reputation + research
Upgrade workshop (more board space, better drop table, faster generator)
Repeat (new orders appear; occasional villain offers / lockout pressure)
Meta loop (hours–days)
Unlock neighborhoods (new customer “house styles” + order templates)
Build your reputation tier (more lucrative orders)
Choose supplier strategy (Locked vs Open)
Advance R&D toward the Freedom Controller
Face periodic Bulb Baron story events that test your build choices

3) Core gameplay systems (MVP-ready)
3.1 Merge board (single board, mobile-native)
Grid: start 5×6 (30 slots).
24 usable slots
3 “fixed stations” (Workbench, Order Inbox, R&D Bench placeholder lock)
3 blocked slots unlocked via upgrades (immediate visible growth)
Interactions (one-thumb friendly):
Drag an item onto a same-tier item → merges instantly.
Long-press item → tooltip (tier, family, value, dependency impact).
Swipe to pan? Avoid unless needed; keep board fully visible.
Quality-of-life (must-have):
“Auto-snap” highlight: when dragging, valid merge targets pulse.
“Undo last move” (very limited: 1 step, cooldown) to reduce fat-finger frustration.
Overflow protection: if board is near full, workbench pauses generation and shows a clear “Merge or fulfill an order.”
3.2 Part families: Standard vs Locked (the strategic heart)
You have two parallel families that share the same tier ladder:
Open-Standard parts (blue/white glow): slower value early, stable long-term.
Locked parts (gold/purple glow, Bulb Baron branding): better output early, but increase Dependency.
How Locked is “better” in a clean, understandable way:
Locked merges have a higher chance to produce a bonus byproduct (cash chip or research chip).
Locked drops start slightly higher tier more often (e.g., Tracks instead of Clips) once the Baron “hooks” you.
This preserves the same verb (merge) while making Locked feel visibly superior—without adding confusing rules.
3.3 Generator (Workbench) — the “spawn” mechanic
The Workbench produces parts on tap with a short cooldown. Typical merge-game pattern, but tuned for respectful pacing.
Tap Workbench → spawns 1 part into an empty slot.
Cooldown is short (seconds) and reduces with upgrades.
Drop table depends on your workshop tier + your current Dependency (subtle villain pressure).
Drop table rules (simple):
Default: mostly Clips, some Tracks
Upgrades: improve odds of Tracks and Segments
High Dependency: increases odds of Locked drops and Locked “promo crates”
3.4 Orders from houses (the “sink” that creates purpose)
Orders are card-like requests displayed in an “Order Inbox” panel.
Each order:
Required items (e.g., 2 Smart Kits + 1 Segment)
Accept/complete button (consumes items)
Rewards: cash + reputation + sometimes research
Order types (MVP):
Basic Install (no trick): teaches loop
Style Match: requires all Standard or all Locked items (teaches families)
Rush: higher payout but soft timer (timer reduces bonus, not hard fail)
Premium Client: requires higher-tier kit, big reputation payout
Order slots:
Start with 2 visible orders, can upgrade to 3–4.
3.5 Workshop upgrades (your main “spend”)
Upgrades are immediate and visual, so spending feels satisfying.
Upgrade categories:
Space: unlock blocked slots / expand board (most tangible)
Workbench: faster cooldown, better drop odds
Quality Tools: small bonus cash on merges
Logistics: more order slots; occasional “priority order”
R&D Bench: unlock research earning and the Freedom Controller path

4) The villain mechanic: Dependency (clean, legible, and fair)
4.1 Dependency meter
A single meter 0–100 shown near the top bar with clear thresholds.
Dependency increases when you:
Use Locked parts in merges
Buy/accept Bulb Baron “locked crates”
Fulfill orders with Locked kits (small increase)
Dependency decreases when you:
Fulfill orders using Open-Standard kits (small decrease)
Invest in Open-Standard upgrades (one-time decrease + cap reduction)
Spend Research to “refactor” your supply chain (mid-game)
Use Freedom Controller (late-game)
4.2 What Dependency does
 (the pressure curve)
Dependency is only meaningful if it changes play—not just flavor text.
Threshold effects (example):
20+: Baron offers appear more frequently (temptation)
40+: 1 in ~5 new orders becomes “Baron Certified” (Locked preferred for full reward)
60+: Some installs are Locked Required (if you complete with Standard, you take a refund/reputation hit)
80+: Locked generator bias increases; Open parts drop less often
100: Lockout Event triggers (the boss moment)
This creates a readable arc: the player feels the hook tightening.
4.3 Fairness rules (so it doesn’t feel like a trap)
You always have some path out (Open upgrades + R&D).
“Locked Required” orders never appear before the player has seen:
the Dependency meter,
a warning threshold message,
the R&D tease (“Freedom Controller blueprint discovered”).
Refund penalties are soft early (cash loss), only later include reputation hits.

5) R&D and the “Freedom Controller” (long-term aspiration)
5.1 Research points (separate from cash)
Research is earned primarily through:
Open-Standard merges
Completing Open-Standard orders
Occasional “Lab Request” order cards
This is deliberate: it makes Open playstyle feel like “slow money, fast independence.”
5.2 R&D tree (MVP version)
Keep it tiny but meaningful.
Nodes:
Open Standardization I: reduces Dependency gain from locked merges slightly
Open Standardization II: increases Open drop odds slightly
Freedom Controller Blueprint: unlocks crafting recipe
Freedom Controller Build: craft an item that can “unlock” a locked kit
5.3 What the Freedom Controller does (simple and powerful)
It is a consumable or tool (pick one for MVP; I recommend consumable for clarity).
Use it on a Locked Smart Kit / Premium System → converts it into an Open-Compatible Kit.
Open-Compatible Kits can satisfy “Locked Required” orders without penalties.
This makes the late game feel like liberation: you can still exploit locked value, but you’re no longer owned by it.

7) The Lockout Event (the “boss moment”)
Trigger
When Dependency hits 100 (or a scripted story milestone in MVP).
Fiction
The Bulb Baron pushes a “firmware update” that breaks compatibility: certain installs reject Open kits unless they’re certified.
Gameplay structure (3 short phases)
Phase 1 — Shock (30 seconds):
A forced new order appears: “Locked Required.” The player attempts completion, gets blocked/refund warning. Clear messaging: “Your workshop is dependent.”
Phase 2 — Response choice (2–5 micro-sessions):
Option A: Buy Baron’s “Emergency Locked Crate” to brute-force (fast but deepens dependency)
Option B: Complete 2–3 “Lab Request” orders to earn Research and craft Freedom Controller
Phase 3 — Liberation payoff (instant):
Use Freedom Controller on a locked kit or to satisfy the locked requirement, ending the lockout. Dependency drops to a safer threshold (e.g., 60) and the player unlocks ongoing R&D nodes.
Why this works: it turns the theme into consequences the player feels, not a cutscene.

1. The Core Style: Isometric Minimalism
The most accurate term for this is Isometric Minimalist Art. It’s defined by a lack of perspective (lines don't vanish into the distance), which allows for the "impossible" geometry puzzles seen in the game.
Key Visual Pillars:
Low-Poly (Refined): While the models have low polygon counts, they aren't "blocky" like Minecraft. They are clean, smooth, and precisely engineered.
Flat Shading & Soft Gradients: There are no gritty textures (no dirt, wood grain, or stone cracks). Instead, depth is created through subtle color gradients and clean shadows.
Pastel & Triadic Palettes: The colors are often soft, curated, and high-contrast, making the interactive elements (like the red character) pop against the teal background.

​​Addendum: Narrative & Villain Story Layer (built for mobile merge play)
A quick note on how this is loosely based on a real life enterprise
This is loosely based on a real life company I will refert to as “The enterprise” (don’t call them “the enterprise in the real game. Give the company a name).
The enterprise describes itself as a permanent, programmable outdoor lighting company, with an origin story starting in 2010 tied to founder (redacted) wanting a better solution than climbing ladders in winter; it also emphasizes a patented channel solution and growth to hundreds of authorized dealers.  
The enterprise “Become a Dealer” materials describe a dealer licensing / protected territory model: territories can start around a zip code, expansion requests are at The enterprise’s discretion, and they describe quotas and the possibility of opening/resizing a territory if performance is low.  
The enterprise markets a controller + app ecosystem (e.g., “Edge” remote access app, “millions of colors, patterns, animations”).  
A enterprise dealership flyer (hosted on a enterprise-related domain) describes exclusivity being contingent on conditions and states they “reserve the right to reassign” non-compliant/poor-performing dealership areas.  
What is visible is a fairly typical centralized model: protected territories, rules/quotas, and a proprietary app/controller ecosystem. So the best approach is: use those structural ingredients as satire (zip-code baronies, “certified controllers,” “firmware updates”), while keeping the villain fully fictional and gameplay-first.
To avoid legal/ethical pitfalls and keep this shippable:
Don’t use the name of any real company in the real world, real logos, or real person likenesses in-game.
Don’t imply the real company/founder is “villainous” or doing wrongdoing.
Do lean into universal lock-in dynamics (exclusive territories, certification, app updates, quotas) as the villain’s tactics.
Everything below is designed to preserve playability and micro-session flow.

1) Narrative design rules for merge games (what to do and what not to do)
Do (best practice)
Deliver story in 2–6 second bites
Story is a “seasoning,” not the meal. If it interrupts the merge loop, it hurts retention.
Tie story to mechanics, not cutscenes
The villain shouldn’t monologue; the villain should appear as the offer card that raises Dependency, the “certification” requirement on orders, and the lockout event.
Use “story as reward”
Completing an order unlocks a tiny beat: a customer reaction, a neighborhood postcard, or a villain memo. Story should feel earned.
Make every story moment skippable + re-readable
One tap to skip; a “Story Log” to reread later. This respects adults, noisy environments, and repeat sessions.
Repeat a few motifs until they become satisfying
Players love recurring jokes and predictable formats:
“BaronFax” memos with absurd fine print
“GlowMail” from customers
“Workshop radio” announcements when Dependency hits thresholds
Keep character count tiny in MVP
MVP cast = 3–5 recurring characters. Everyone else appears as flavor text on orders.
Make choices feel like “I did this”
If I choose locked parts, the Baron praises me, the meter rises, and later I face certification installs. Consequences should be legible and narratively acknowledged.
Don’t (common failures)
Don’t put lore before the first merge
No intro cinematic you can’t skip. Your first 10 seconds must be merging.
Don’t force reading to understand rules
Tutorials must be forced actions + feedback, with story as a wrapper.
Don’t over-write
Mobile narrative should be punchy. Long paragraphs are churn fuel.
Don’t make the villain purely evil
“Pure evil CEO” gets old fast. Better: the villain is charming, rational, and sincerely believes “standardization” is good—while still pressuring lock-in.
Don’t punish without warning
If Dependency causes refunds, the game must warn clearly with both UI + a narrative beat (“Baron Certified clients won’t accept unlicensed kits”).

10) “Greatness” checklist specifically for narrative in a merge tycoon
Must-have for greatness
A villain who is also a UI system (the Baron is Dependency + offers + lockout)
Story beats that always coincide with a reward or a new mechanic
A re-readable story log (for players who care)
Narrative clarity that reduces perceived unfairness (refunds feel “caused,” not random)
Humor with restraint (chuckle, not cringe)
Avoid if you want greatness
Long dialogue trees (merge players didn’t come for that)
Heavy lore dumps
Unskippable sequences
Punishment framed as moral judgment (“you were greedy”)—instead frame it as system dynamics (“the Baron tightened the contract”)
Too many named NPCs before the player is emotionally invested

11) Implementation notes (how to build it without derailing production)
Narrative system as data (recommended)
Create a simple “Story Beat” data object:
trigger_type: tutorial_step / dependency_threshold / upgrade_purchased / order_completed / neighborhood_unlocked / event_started
priority: blocks_play (never) / overlays / inbox_only
text_line_1, text_line_2
speaker: mentor / baron / customer / system
once_only: true/false
cooldown_seconds: prevent spam
This lets you iterate narrative without engineering churn.
